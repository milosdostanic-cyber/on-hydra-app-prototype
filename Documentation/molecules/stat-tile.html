Decision: new molecule

Why new, not an upgrade

No Hydra molecule shows a labelled count. The closest Hydra component is the Statistic atom (162:345) →: a vertical stack (title above number, gap paddingLG) with an optional icon and button. It cannot produce the row layout (label left, value right), the tile container or the tone accent through its properties, and atoms are out of scope. So the Stat Tile is a small new molecule. It uses exactly the Statistic text tokens (Base/Normal colorTextDescription for the label, Title/Heading 3 colorText for the value), so both read as one family.

Nested atoms

None. No occurrence uses an icon, button or tag inside the tile, so none is nested and no slot is added.

Related

Statistic (atom): a single highlighted number without a tone. Outcome Summary (audit candidate): a panel with a title and description that nests a row of Stat Tiles. Progress Summary Bar (audit candidate): progress of a running task, not a count.

Target in Hydra

Component description (Hydra format, to paste in BUILD)

A Hydra product composition: one labelled count with a semantic tone accent, shown alone or in a row of tiles. It is not an Ant Design component.

Code: proposed src/ui/StatTile.tsx. It replaces the hand-built cards in src/bom/pages/BomMatchingPage.tsx, src/bom/components/BomGuidedReviewCompletePanel.tsx and src/spec/pages/SpecExportPage.tsx. label → Typography.Text type="secondary"; value → Heading 3 text; tone → border-inline-start colour (token.sizeUnit wide).

Properties:
– tone (success | warning | error | info) → left accent colour
– ✏️ label → the muted label
– ✏️ value → the count

Use for: a row of 2–4 outcome counts (accepted / denied / undecided, ready / skipped / needs attention). Put tiles in a horizontal row with gap margin and set each tile to FILL.
Do not use for: a single highlighted number without a tone (use Statistic), KPI cards with charts or trends, clickable filters, progress (use a Progress Summary Bar).

Code note

The prototype draws the same tile three times in code (BomMatchingPage.tsx, BomGuidedReviewCompletePanel.tsx, SpecExportPage.tsx), and the colours drift from Figma there too. Matching results: Total uses a blue primitive, "Needs attention" uses colorWarning (Figma: colorErrorBorder) and Skipped uses colorWarningBorder (Figma: colorWarning). The guided-review panel stacks label over value in code but uses a row in Figma. A future StatTile component would fix all three; no code is changed by this plan.

Admin: adopt Stat Tile or keep the Statistic atom (decided: keep the atom)

Admin · RN Admin Release Notes Admin · Bulk upload · Success · Open in Figma →

Recommendation: adopt

  • Same meaning as BOM 2.14: counts of imported vs skipped rows after an import. One meaning should have one pattern across modules.
  • The Admin instances already override the atom: number weight SemiBold (the atom is Medium) and a coloured number. "Rows skipped" uses colorPrimary, which is not a status colour. With Stat Tile, the tone moves to the accent (success, warning) and the overrides disappear.
  • It fits the 480 px modal: two tiles FILL in a row are about 210 px each, the same width as today.
  • The Statistic atom stays in Hydra for a single highlighted number without a tone (its AntD use).
  • Trade-off: the result modal becomes left-aligned tiles under a centred check icon and title. If you prefer the centred look, choose "keep"; then the Admin card is dropped and Admin is unchanged.

Open questions at plan time

Decided at approval: Admin keeps the Statistic atom (no Admin card), and the shadow is a fixed boxShadowTertiary style.

  • Admin: adopt Stat Tile or keep the Statistic atom?

    Recommendation: adopt Stat Tile (tone success / warning) in the Release Notes bulk-upload result. Reasons: it shows the same kind of data as BOM 2.14 (imported vs skipped), the Admin instances already override the atom (SemiBold weight, coloured numbers, and colorPrimary used as a warning colour), and one pattern per meaning is easier for users and developers. Keep the Statistic atom for a single highlighted number without a tone. If you choose "keep", the Admin card is dropped from Replace in modules and nothing changes in Admin.

  • Warning and info accent: the pale …Border family or the solid colours?

    The plan uses colorWarningBorder (#ffe58f) and colorInfoBorder (#91caff) so all four tones come from one token family, as SPEC does. BOM today uses the stronger colorWarning (#faad14) and colorInfoActive (#0958d9). If you prefer stronger accents, use colorSuccess / colorWarning / colorError / colorInfo for all four tones instead; mixing families is not recommended.

  • Accent width token.

    Bind the 4 px left stroke to Size/Size/sizeXXS (the only 4 px Hydra token, matching token.sizeUnit in code). That variable has no stroke scope, so it does not appear in the stroke picker; the binding still works by script. The alternative is a fixed 4 px value. No variable will be created or edited either way.

  • No "neutral" tone.

    No occurrence has a tile without a tone, so none is planned. Say if you want one (accent colorBorderSecondary) for future use.

  • Replace-in-modules cards: full rows.

    Each card will hold the whole row of tiles (2–4 instances side by side, FILL) so it looks like the module screen. The alternative is one instance per card (27 cards). The plan uses full rows (9 cards).
