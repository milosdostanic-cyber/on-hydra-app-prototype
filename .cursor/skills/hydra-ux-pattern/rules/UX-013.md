# UX-013: Tags, Badges and Colours in Tables

- **Category:** Tables / Tags
- **Status:** Approved (2026-11-13, Milos). Brings the tag and badge rules from
  `table-tags-badges.mdc`, `content-file-type-tags.mdc` and `type-tag-colors.md` (user rules,
  2026-11-06 and 2026-11-09) into this registry so the whole team can use them.
- **Standard:** Each kind of value in a table has one treatment. A record status is a dot badge. Match
  quality is a status tag. Only "Type" columns and file types get colourful tags, and every value keeps
  the same colour on every screen. Everything else is a neutral tag or plain text.
- **Reference:** Admin - RSFC Users table (Type tags, Status badge); Part Search - RSFC Drawings column
  (file type tags); DS Hydra Ant Design - DS, Tag page, section "Patterns", "File type tags" `2463:177`.

## Spec

| Value kind | Figma | Code | Examples |
|---|---|---|---|
| Record status or access state | `Badge__Status`, `Table cell` type=badge, dot and label, left aligned | antd `<Badge status text />` | Draft, Published, Active, Error, Enabled, Disabled, Allowed, Not allowed, Ready, Needs review, Included, Excluded |
| Match quality or confidence | `Tag__Status` | Status tag (success, warning, error) | Exact match, Substitute, High, Medium, Low, Added manually |
| File type | `Tag__Colorful`, border on, colour from the file type table | Colourful tag through the shared file type helper | RFA, PDF, DWG |
| Small closed "Type" column | `Tag__Colorful`, border on, colour from the Type table | Colourful tag with the preset from the Type table | Admin, User, Feature, Fix |
| Roles and labels users create | Neutral `Tag` | antd `Tag` with no colour | Users "Roles", Knowledge Center categories |
| Everything else | Plain text | Plain text | Counts, quantities, dates, Yes and No, version, unit, category, feed format |

### File type colours

| File type | Colour | Role |
|---|---|---|
| RFA | `blue` | Revit family, the main BIM file |
| STEP | `geekblue` | Neutral 3D solid |
| PDF | `cyan` | Dimensioned reference drawing |
| DWG | `orange` | AutoCAD drawing (`Tag__Colorful` has no `red`) |
| IGES | `magenta` | Neutral geometry exchange |
| SAT | `purple` | ACIS solid exchange |
| IEZ | `green` | Fabrication CAD MEP package |
| TXT | `gold` | Revit support file, bundled with RFA, never its own download |
| PNG | `lime` | Preview image |

An unknown file type uses the neutral default tag, never a new colour. Source list: Confluence
"Content File Types".

### File types in a table cell

- Show at most 3 file type tags. More types add a neutral `+X` tag (`Tag`, default, border on), where
  X is the hidden count.
- Hovering `+X` opens a light `Tooltip` (`colorBgElevated`, placement top) with the hidden types as the
  same colourful tags. Do not use a `Popover` and do not list them as plain text.
- The column is wide enough for 3 tags plus `+X` on one line.
- The order follows the record's file type list. Do not regroup types.

## Rules

- A record status is never a tag (`Tag__Status` or `Tag__Colorful`).
- A count is never a tag (see UX-011).
- A value keeps one colour on every screen and in every module, in Figma and in code.
- Colourful tags are for Type columns and file types only.
- Colours can repeat across different columns, but never inside one column.
- Tag and badge columns align left.
- Do not add tag colours, tokens or new tag components for this.

## Applies when

- Table cells, and record cards or lists that show the same values (for example a match details
  modal), in every module file and in code.

## Does not apply

- KPI numbers on dashboard tiles and badge counters on icons (notifications).

## Implementation (Figma)

- Status: `Table / Table cell` with type=badge and the `Badge__Status` status that matches the value.
- Tags: DS `Tag__Colorful` with border on, layer name `Tag__Colorful / <value>`, `color` variant from
  the tables above. Never detach the instance or override the fill.
- The DS `Table cell` holds one tag only. A cell with several file type tags is a local Auto Layout
  frame named `Drawings cell` that copies the cell's padding, gap, fill and bottom border variables.

## Validation (per candidate)

1. Find the value kind in the Spec table.
2. Check the component: badge, status tag, colourful tag, neutral tag or plain text.
3. For a colourful tag, check the colour against the Type or file type table.
4. Check that the cell is left aligned and that file type cells follow the 3 plus `+X` rule.

Anything else is a finding. A value that is not in either colour table is **Needs review**.

## Fix (only when explicitly requested)

- Wrong component: swap the instance (for example `Tag__Status` to `Badge__Status` for a status) and
  keep the label.
- Wrong colour: change only the `color` variant to the one in the table.
- Never change copy, column order or column width as part of this fix.

## Open questions

- `on-hydra-app` Content file manager (`fileTableRows.ts`, CON-228) uses a different colour map:
  PDF `red`, TXT `purple`, STEP `green`, IGES `cyan`, PNG `magenta`, SAT `gold`, plus ITM `geekblue`
  and VRML `lime`. This rule's table has no ITM or VRML. Needs a design decision before either side
  changes.
