# UX-009: State Card Fills the Height

- **Category:** Layout / States
- **Status:** Approved (2026-11-11, Milos)
- **Standard:** When the main content card shows a **state instead of data** (start / first use,
  loading, empty, no results, error), the card is **H → FILL**: it stretches to the bottom of the
  work area (page padding 24 below it). There is never empty page background under a state card.
- **Reference:** BOM - RSFC · "1.3 Start, category list open" `Search Card` `7573:188449`.

## Spec

| Layer | Vertical sizing |
|---|---|
| Screen frame | FIXED or HUG, `minHeight` 970 (UX-006) |
| `Body`, `Right Work Area` | FILL |
| `Content` (page padding 24) | FILL |
| Page header | HUG |
| State card (e.g. `Search Card`) | **FILL** |
| Toolbar inside the card | HUG (UX-007) |
| State block (`Empty State Block`, `Loading`, `Result`) | FILL, content centred |

In code: the work area is a vertical flex column with `min-height: 100%` (or `100vh` minus the top
bar); the page content is `display:flex; flex-direction:column; flex:1`; the state card is `flex:1`
and its body centres the state block. The card grows with the window, never stops at content height.

## Applies when

- Any screen whose main card shows a start, loading, empty, no-results or error state, in every
  module file and in the prototype code.

## Does not apply

- Cards that show a data table or list: they hug their content (rows + footer).
- Cards in a grid or with other content below them.
- Modals and drawers.

## Validation (per candidate)

1. Does the main card show a state instead of data? No → skip.
2. Card and every parent up to `Body` FILL vertically, and the gap below the card = page padding (24)?
3. Yes → **Already correct**; otherwise list the HUG layer and the gap.

## Fix (only when explicitly requested)

Set `Content` and the state card to `layoutSizingVertical = FILL`, the state block to FILL. Keep
the page header HUG. Verify the gap below the card is 24.
