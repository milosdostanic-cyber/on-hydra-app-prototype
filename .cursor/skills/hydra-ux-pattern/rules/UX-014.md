# UX-014: Modal Placement on a Screen

- **Category:** Modals
- **Status:** Approved (2026-11-17, Milos)
- **Standard:** An open modal on a screen is a Hydra DS `Modal__Overlay` instance, placed as the
  last child of the screen frame and covering it, with the DS `Modal` inside. The modal body is a
  local content component placed in the Modal's `.slot__component`. The Modal and the slot hug the
  content, so the content sets the width. Never a hand-built overlay frame with a modal frame.
- **Reference:** BOM - RSFC (`Ht3Up5MlRAKjK7eCuAy05L`), BOM Flows screen "2.6 — Parsing review ·
  Row edit drawer" `5570:200450` (content `BOM / Parsed Line Editor`), and Concepts "A5 · Match
  details" (overlay `7750:8238`, content component `Prototype / Match details content` `7750:8202`).

## Spec

| Part | Rule |
|---|---|
| Overlay | DS `Modal__Overlay` instance. Last child of the screen frame, absolute position, covers the whole screen. Do not detach it |
| Modal | The DS `Modal` in the overlay's "🎰 modal" swap. Title, close and buttons are set with its properties (title text, show close, show button primary, secondary and so on) |
| Body | A local component that holds only the modal body, placed in `.slot__component`. Keep it in the page's Components section with a short description |
| Size | Modal and slot set to Hug, width comes from the content component. No fixed modal width unless the code sets one; then the content component has that width minus the side padding |
| Padding | Content Wrapper top and bottom padding `paddingXS` (8px), as in the DS Modal. Header and footer stay as in the DS unless the code sets other values |
| Position | The `Modal__Overlay` position variant that matches the code. antd's default modal sits 100px from the top |
| Background | The screen under the overlay is the real screen state the modal opens from, not an empty frame |

## Applies when

- Any screen in a module file that shows an open modal or dialog: edit forms, details, confirms.
- New modal screens and changes to existing ones.

## Does not apply

- Drawers and popovers, unless the DS uses the same overlay for them.
- Component documentation frames that show the modal on its own, without a screen.
- Archive, Old, WIP and Exploration pages.

## Implementation

- Build the body first as a local component from DS instances and tokens.
- Insert a `Modal__Overlay` instance as the last child of the screen frame, set it to absolute
  position at 0, 0 and the size of the screen.
- Set the Modal properties, then remove the placeholder from `.slot__component` and append an
  instance of the body component.
- Set Modal and slot to Hug. Check the width and height against the code or the spec.
- In code the matching pattern is the antd `Modal` from `src/ui/antd` with the body as its own
  component (for example `PartCrossReferenceMatchModal`).

## Validation (per candidate)

1. Is the overlay a DS `Modal__Overlay` instance, last child of the screen, absolute, covering it?
2. Is the modal the DS `Modal` inside the overlay, not a frame?
3. Is the body a component instance in `.slot__component`?
4. Do Modal and slot hug the content, and is the Content Wrapper padding 8px top and bottom?
5. All yes means **Already correct**. A hand-built overlay or modal frame is a finding. If the body
   would need a new component and nobody approved it yet, mark it **Needs review**.

## Fix (only when explicitly requested)

Rebuild as in Implementation. Turn the existing body into a local component (or reuse one that
exists), place it in the slot, delete the hand-built overlay, then compare screenshots before and
after. Do not change the body content.
