# UX-008: Status Column Placement

- **Category:** Tables / Column order
- **Status:** Approved (2026-11-11, Milos). Figma and code fixes not applied yet.
- **Standard:** In every table, the record **Status column comes right after the name (identity)
  column**: `☐ | (#) | Name | Status | other data ... | Actions`.
- **Reference:** SPEC - RSFC · "01 — Project SPEC list" (`SPEC name | Status | Review progress | ...`).

## Why

- Columns are ordered by importance left to right; users scan the left side first (F-pattern).
  Name says *what* the row is, Status says *what state it is in*: the two things looked for first.
- Wide tables scroll horizontally; a status near the end gets cut off. Next to the name it stays visible.
- Status (information) and Actions (things to do) stay apart; Actions stays last (UX-004).
- One placement everywhere, so users learn where to look once.

## Spec

| Part | Rule |
|---|---|
| Position | Directly after the identity column(s). Identity = the column that names the row (Project name, SPEC name, Title, Feed Name, Feature Module, Original part / From your file). Leading `#` and selection checkbox stay before it |
| Header | "Status" (or the existing specific label, e.g. "Access Status", "Outcome") |
| Cell | `Badge__Status` dot + label, left aligned (UX-013) |
| Width | Fixed, as wide as the longest status label + cell padding |

## Applies when

- Columns that show the state of the row's record: Status, Access Status, Outcome, File state.
- Every module file and the prototype code.

## Does not apply

- Confidence / match columns (Quality, Match score, Match): they are not status and keep their place.
- Event logs where time is the identity (CFM Receipts `Timestamp | User | Action | ... | Status`): keep as is.
- Tables without a status column.

## Implementation

- Figma: move the Status column frame to the index after the identity column inside `Columns`
  (Auto Layout reorder). Keep instances, widths and the FILL column unchanged.
- Code: reorder the `columns` array so the status column follows the name column.

## Validation (per candidate)

1. Does the table have a record-status column? No → skip.
2. Is it directly after the identity column? Yes → **Already correct**; no → finding with current position.
3. Identity unclear (logs, pickers) → **Needs review**.
