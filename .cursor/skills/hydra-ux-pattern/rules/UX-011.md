# UX-011: Counts and Match Quality in Tables

- **Category:** Tables / Tags
- **Status:** Approved (2026-11-12, Milos, "fix all" on audit findings BOM-NR-002, BOM-NR-004)
- **Standard:** A number or count in a table cell ("2 matches", "142") is **plain text**
  (`Table cell` type=text), never a tag. Match quality / confidence (Exact match, Substitute, High,
  Low) is a tone tag `Tag__Status`, never `Tag__Colorful`. `Tag__Colorful` stays for Type columns and
  file types only. The full tag and badge rules are in UX-013.
- **Reference:** BOM - RSFC · BOM Hub "Items" column (plain text count).

## Spec

| Value kind | Treatment |
|---|---|
| Count / number | `Table cell` type=text, `show tag` off, label = "2 matches" |
| Match quality / confidence | `Tag__Status` (success = exact/high, warning = substitute/medium, error = low) |
| Type / file type | `Tag__Colorful` (see UX-013) |
| Record status | `Badge__Status` (unchanged) |

## Applies when

- Table cells and record cards/lists that show the same values (e.g. match details modal), in every
  module file and in code.

## Does not apply

- KPI numbers in dashboard tiles; badge counters on icons (notifications).

## Validation (per candidate)

1. Is it a count → plain text? 2. Is it match quality → `Tag__Status`? Otherwise finding.

## Fix (only when explicitly requested)

Counts: turn `show tag` off and move the text into the cell label. Quality tags: swap
`Tag__Colorful` → `Tag__Status` with the matching status, keep the text.
