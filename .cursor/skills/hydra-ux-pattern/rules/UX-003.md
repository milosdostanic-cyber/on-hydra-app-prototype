# UX-003: Module Entry Page Title

- **Category:** Typography / Page header
- **Status:** Approved (2026-11-11, Milos)
- **Standard:** The title block on a module's first (entry) page is a heading + description pair:
  heading `Title/Heading 2` in `Color/Neutral/Text/colorText`, description `Large/Normal` in
  `Color/Neutral/Text/colorTextDescription`, stacked vertically with a `Size/Padding/paddingXXS`
  (4px) gap.
- **Reference:** BOM - RSFC, "Get Started Container" `7560:210697`
  (https://www.figma.com/design/Ht3Up5MlRAKjK7eCuAy05L/BOM---RSFC?node-id=7560-210697)

## Spec

| Part | Layer | Text style | Fill token | Sizing |
|---|---|---|---|---|
| Container | Frame, Auto Layout vertical, padding 0 | — | none | Hug × Hug |
| Gap heading → description | `itemSpacing` | — | `Size/Padding/paddingXXS` (4px) | — |
| Heading | Text, e.g. "Get started" | `Title/Heading 2` (Barlow SemiBold 30/38) | `Color/Neutral/Text/colorText` | Hug |
| Description | Text, one sentence on what the user can do here | `Large/Normal` (Barlow Regular 16/24) | `Color/Neutral/Text/colorTextDescription` | Hug |

Context in the reference: the title block sits on the left of a horizontal header row
(`space-between`, vertically centred) with the page's primary action on the right
(`Button` primary, size large, e.g. "New BOM Project"). The header row is the first child of the
page content area. The primary action is optional; the title block spec above is what this rule
enforces.

## Applies when

- The first / landing page of a module (entry point, "Get started", overview before any record is
  opened) that shows a page-level title with a short description under it.
- Any module file (Admin, Content, Release Notes, Part Search, Unified Search, BOM, SPEC).

## Does not apply

- Detail pages, wizard steps, modals, drawers, cards and section headings inside a page.
- Breadcrumb / page header components from the DS that carry their own title style.
- Empty-state titles (they follow the empty-state pattern, not this one).
- A title with no description line: check heading style and colour only; do not add a description.

## Implementation

- Use the DS text styles `Title/Heading 2` and `Large/Normal` (never local styles or raw font values).
- Bind fills to `colorText` (heading) and `colorTextDescription` (description); never raw hex,
  `colorTextSecondary` or primitives.
- Bind the container's `itemSpacing` to `Size/Padding/paddingXXS`; never a raw 4.
- Heading copy is short (2–4 words); description is one plain-language sentence.

## Validation (per candidate)

1. Is this the module's first/entry page title (not a detail, step or section heading)? If unsure → **Needs review**.
2. Heading text style = `Title/Heading 2`, fill = `colorText`.
3. Description text style = `Large/Normal`, fill = `colorTextDescription`.
4. Container is vertical Auto Layout with gap bound to `paddingXXS`.
5. All match → **Already correct**. Any mismatch → finding (list each property, before → expected).

## Fix (only when explicitly requested)

1. Apply the text styles and rebind the fills to the tokens above.
2. Set/bind the container gap to `Size/Padding/paddingXXS`; wrap heading + description in a
   vertical Auto Layout frame only if they are not already grouped and doing so does not break the
   parent layout (otherwise **Needs review**).
3. Do not change copy, the right-side action, or anything outside the title block.

After the fix: re-read styles, fills and gap; screenshot before/after.
