# UX-005: Search Field = Input + Search Button

- **Category:** Filters / Search controls
- **Status:** Approved (2026-11-11, Milos)
- **Standard:** A page-level search is a DS `Input` (search icon on the left) followed by a DS
  `Button` (type primary, label "Search"), both the same size, inside a horizontal Auto Layout
  frame named `Input and Button Container` with an `itemSpacing` bound to
  `Size/Padding/paddingXS` (8px). Never use the DS `Input__Search` component (input with an
  attached icon button) for page search.
- **Reference:** Unified Search - RSFC, page "Banners", `Input and Button Container` `1033:10062`
  (https://www.figma.com/design/usBJj4PPK8naOgJdi31Lgt/Unified-Search-RSFC?node-id=1033-10062).
  Also Part Search - RSFC "Category Page" `11114:5858`, and BOM - RSFC "Part Cross-Reference" screens.

## Spec

| Part | Component / value |
|---|---|
| Container | Frame `Input and Button Container`, Auto Layout horizontal, counter axis centred, padding 0, `itemSpacing` = `Size/Padding/paddingXS` |
| Input | DS `Input` (`20cab57b…`), `size=large` on page-level search (`medium` only inside dense toolbars), `show icon left = true`, icon left = `SearchOutlined` (`aed839ec…`), no prefix/suffix/right icon, label and caption hidden |
| Input text | Placeholder says what can be searched, e.g. "Search by figure number, SKU, description or keyword". With a typed query use `filled=true` |
| Button | DS `Button`, `type=primary`, same `size` as the Input, label "Search", no icons |
| Width | Container FILL in its row; Input FILL (or FIXED when the row is centred, e.g. 600 on a hero banner); Button HUG |

Other controls in the same row (category `Select`, filters) are independent controls: keep the
UX-001 20px gap between them and the container. The 8px gap applies only inside the container.

## Applies when

- Any page or panel whose main job is searching (part search, cross-reference, catalogue search,
  hero/banner search).
- Any module file (Admin, Content, Release Notes, Part Search, Unified Search, BOM, SPEC).

## Does not apply

- Search-as-you-type filters inside a table toolbar (an `Input` with a search icon and no button,
  e.g. "Search items…" above a table) and filter rows with a "Clear filters" button.
- Search inside `Select` / dropdown menus.
- Internals of DS components.

## Implementation

- Build from DS instances only: `Input` + `Button`. Do not detach; set icon and text through
  component properties.
- Bind the container gap to `Size/Padding/paddingXS`; never a raw 8.
- Input and Button share one `size`.

## Validation (per candidate)

1. Is this a page/panel search (submits a query), not a live table filter? If unsure → **Needs review**.
2. Uses `Input` + `Button` (not `Input__Search`)?
3. Input: search icon left, same size as the Button; Button: primary, "Search".
4. Container gap bound to `paddingXS`.
5. All match → **Already correct**; otherwise list each mismatch.

## Fix (only when explicitly requested)

1. Insert `Input and Button Container` where the `Input__Search` sat (same index, same sizing).
2. Add `Input` (size of the old control, icon left `SearchOutlined`, same text) and `Button`
   (primary, same size, "Search"); bind the gap.
3. Remove the old `Input__Search` instance. Leave sibling controls and row gaps unchanged.

After the fix: re-read the instances and gap, screenshot before/after.
