# UX-004: Table Actions Column Alignment and Width

- **Category:** Table patterns / Alignment
- **Status:** Approved (2026-11-11, Milos). Width rule added the same day.
- **Standard:** The Actions column is the last column of a table. Its header label and its cell
  content are **right-aligned** to the same right edge (16px cell padding), never centered. The
  column is exactly as wide as its widest set of actions plus cell padding.
- **Reference:** SPEC - RSFC · "01 — Project SPEC list" Actions column `8029:4067` (after fix).

## Spec

| Part | Rule |
|---|---|
| Position | Last visible column; pinned right when the table scrolls horizontally |
| Width | Fixed = widest cell content in the column (sum of visible actions + gaps) + left/right cell padding (16 + 16). Never narrower than the "Actions" label + 32. Another column (usually the main text column) is FILL and absorbs the difference |
| Header label | "Actions" (or "Action" when every row has exactly one), same text style and colour as other headers, right-aligned, 16px right padding, no sort or filter |
| Header without visible label | Allowed only when the column holds a ⋯ menu alone; the cell still needs the accessible name "Actions" |
| Cell alignment | `Table / Table cell` Auto Layout horizontal, primary axis **MAX (right)**, padding 16/16 |
| Gap between actions | 8px (`Size/Padding/paddingXS`) |
| Order (left → right) | Main text action first, ⋯ overflow menu always last at the far right |
| Visible actions | Max 2 visible plus ⋯. Rare or destructive actions (Delete) go into ⋯; Delete may stay visible only when it is the row's only action |
| Edge alignment | Right edge of the last control in each cell lines up with the right edge of the header label |

## Applies when

- Any data table in the module files with a row-actions column (header "Action"/"Actions", or a
  last column of buttons, links or ⋯ menus per row).
- Built from `Table / Table Item / Header Item` + `Table / Table cell`, or any table-like column layout.

## Does not apply

- Bulk action bars above or below the table (they follow their own toolbar pattern).
- Inline link values inside data cells (e.g. a record name that opens a detail); see UX-002 for their colour.
- Checkbox / selection columns and expand-row chevrons (first column, left/centre by Ant default).
- Internals of DS components (only check instance overrides and module-level cell frames).
- Content File Manager screens while working on BOM (`AGENTS.md`).

## Implementation

- Cells: set the cell frame's primary axis alignment to right (`MAX`); keep padding 16/16 and bind
  the gap to `Size/Padding/paddingXS`. Do not detach or replace the button instances.
- Header: right-align via **instance overrides** on the DS `Header Item` (allowed, the instance stays
  linked): set `primaryAxisAlignItems = 'MAX'` on every horizontal Auto Layout frame between the
  instance and the label text (`Header`, `Wrapper`), and set the label's `textAlignHorizontal = 'RIGHT'`
  (the label is often FILL width, so frame alignment alone does not move the glyphs). An `align`
  variant on the DS component would be cleaner later, but is not required.
- Width: resize the column frame to the target width, keep it FIXED horizontally and keep its
  vertical sizing (HUG). Header and cells are FILL and follow.
- Reordering actions, moving Delete into ⋯, or resizing a column in a table with no FILL column are
  design decisions: **Needs review**, not an automatic fix.

## Validation (per candidate)

1. Is this a row-actions column (header "Action(s)" or per-row action controls in the last column)?
2. Is it the last visible column? If not → finding (Needs review: column order).
3. Header label: measure the glyphs, not the text box. Text box FILL with CENTER alignment is still
   centred → finding. Right edge of label = cell padding from the column edge → correct.
4. Cell content: right gap ≈ cell padding and right gap < left gap → correct; otherwise → finding.
   Wide content that nearly fills the cell can read as "centred" by gap maths: check the frame's
   `primaryAxisAlignItems` before reporting.
5. Width: column width = target (±2px) → correct; otherwise → finding. No FILL sibling column →
   Needs review (resizing would change the table width).
6. More than 2 visible actions, or ⋯ not last → **Needs review** (design decision).

## Fix (only when explicitly requested)

1. Cells: `primaryAxisAlignItems = 'MAX'` on each `Table / Table cell` frame in the Actions column;
   bind the gap to `Size/Padding/paddingXS` if raw.
2. Header: the overrides from Implementation (frames MAX + text RIGHT; load the label font first).
3. Width: only when the table has a FILL column; resize, then restore vertical sizing. Confirm the
   table's total width did not change.
4. Never change copy, button variants or column order as part of this fix.

After the fix: re-read values, then screenshot with the figma-console bridge
(`figma_capture_screenshot`, live state). The official `get_screenshot` render can lag behind recent
edits.
