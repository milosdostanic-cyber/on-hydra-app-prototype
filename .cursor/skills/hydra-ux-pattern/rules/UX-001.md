# UX-001: Horizontal Form Control Spacing

- **Category:** Layout / Form Controls
- **Status:** Approved
- **Standard:** 20px horizontal gap between independent form controls in the same logical row,
  using the existing Hydra DS spacing token (`Size/Padding/paddingMD`, resolved value 20; verify in
  `Documentation/ds-inventory.json` before use).

## Applies when

Two or more **independent** form controls sit horizontally in the same logical row (one
Auto Layout group or visually one row), e.g.:

- Input + Input
- Input + Select
- Select + Select
- Select + Input
- Equivalent combinations (date picker, number input, search input, etc. as separate controls)

Each control has its own label/value/state and can be used on its own.

## Does not apply

- Internal component spacing: icon, label, prefix, suffix, addon inside a control.
- Elements forming one logical or composite control (range pickers, input + unit select,
  split/compact groups, input groups with joined borders).
- Table cell internal layouts.
- Vertical spacing.
- Unrelated horizontal layout patterns (button rows, tag lists, breadcrumbs, toolbars of actions,
  card grids, header rows).
- Intentional patterns explicitly defined by the Design System.

Do not enforce 20px between every horizontally aligned element.

## Implementation

- Horizontal Auto Layout with item spacing bound to the 20px DS spacing token.
- Never hardcode the value; no raw `20`.
- Preserve existing instances, variants and component properties; never detach; no new overrides.
- Keep Fill/Hug/Fixed sizing and constraints so responsive behaviour is unchanged.
- Touch only the gap between the controls in the row, nothing else.

## Validation (per candidate row)

1. Identify the row's parent frame and its controls. Are they independent (see Applies / Does not apply)?
2. Is the parent horizontal Auto Layout? If controls are loose children with manual x positions,
   the safe fix is not obvious: **Needs review**.
3. Is item spacing bound to the 20px token (not raw, not another token)? Bound correctly → **Already correct**.
4. Gap measured visually matches 20? A gap faked with spacer frames, padding on a child, or
   differing per pair → **Needs review** unless fix is a pure item-spacing change.
5. Rows with mixed content (controls + buttons) → apply only to the control-to-control gaps; if
   one item spacing covers both, **Needs review**.

## Fix (only when explicitly requested)

Safe corrections, in order of preference:

1. Parent is horizontal Auto Layout with a raw or off-scale item spacing: bind item spacing to the
   20px token.
2. Parent is horizontal Auto Layout with a different DS token: rebind to the 20px token.

Anything else (restructuring to Auto Layout, removing spacers, splitting groups, changing child
sizing) → **Needs review**; do not change.

After the fix: re-read item spacing (bound variable = the 20px token), confirm instances are still
attached, screenshot before/after to confirm no wrap, overflow or resize.
