# UX-007: Table Card Layout

- **Category:** Tables / Layout
- **Status:** Approved (2026-11-11, Milos). Figma fixes not applied yet.
- **Standard:** A table lives in a card with **padding 0**: the table runs edge to edge. Search,
  category and filters sit in a toolbar row **inside the card**, above the table. The result count
  sits inside the card, never above it. Spacing lives on the toolbar and footer rows, never on the card.
- **Reference:** BOM - RSFC · "1.1 — Hub · Project List", table card `5289:21316`
  (and prototype `src/bom/pages/BomSiteProjectsPage.tsx`).

## Spec

```
Card  · padding 0 · radius borderRadiusLG · colorBgContainer · boxShadowTertiary · clip content
├─ Toolbar   padding 16 top/bottom (`padding`) · 20 sides (`paddingMD`) · bottom border colorBorderSecondary
│   ├─ Controls row   Category Select ─20─ [Input ─8─ Search Button] ─20─ filters   ·   right: secondary actions
│   └─ Summary line   optional: "23 parts match 'valve'" + hint · 12 below the controls (`paddingSM`)
├─ Table     FILL width, no side padding (DS header and cells keep their own 16px text inset)
└─ Footer    padding 16 top/bottom · 20 sides · top border colorBorderSecondary
             "Total N items" left (optional) · Pagination right
```

| Part | Rule |
|---|---|
| Card | Auto Layout vertical, padding 0, gap 0, `borderRadiusLG`, fill `colorBgContainer`, effect `boxShadowTertiary`, clip content |
| Toolbar | Auto Layout vertical, FILL, padding `padding` / `paddingMD`, gap `paddingSM`, bottom stroke `colorBorderSecondary` |
| Control size | Every control in the toolbar is `size=medium` (32px): Input, Search Button, Select, filters (UX-005). Reference: BOM Hub toolbar `7560:210708` |
| Every state | The toolbar keeps the same position and 16/20 padding on every state of the screen (start, loading, empty, no results, error), not only when the table is shown. The state block (FILL, own padding) replaces the table below the toolbar |
| Controls order (left → right) | Category `Select` → search (UX-005 `Input and Button Container`, or a live-filter `Input`) → filters / "Clear filters". Gaps between independent controls: UX-001 (20). Secondary actions right-aligned |
| Bulk selection | When rows are selected the toolbar becomes the bulk bar: "N selected" left, bulk actions right (gap `paddingSM`) |
| Summary line | Count and hint text only (`Base/Normal`, `colorTextSecondary` for the hint). No tags (count is plain text) |
| Table | FILL width, edge to edge. Column rules: UX-004 (Actions), UX-008 (Status) |
| Footer | Auto Layout horizontal, FILL, SPACE_BETWEEN (or MAX when no total), padding `padding` / `paddingMD`, top stroke `colorBorderSecondary` |
| Empty / no results / loading | Same card, same toolbar; the table area is replaced by the state block (empty state rules in `Documentation/hydra-ux-patterns.md` §2) |

## Applies when

- Any list of records shown as a data table inside a card, in every module file (Admin, Content,
  Release Notes, Part Search, Unified Search, BOM, SPEC) and in the prototype code.

## Does not apply

- Tables inside modals and drawers (the modal body padding applies; the table is still FILL).
- Small preview tables inside another card (e.g. BOM Export preview): **Needs review** per case.
- Page-level hero search on a landing page that has no table yet.
- Content File Manager while working on BOM (`AGENTS.md`).

## Implementation

- Set card padding to 0 and move spacing to the toolbar and footer frames; bind every value to the
  DS spacing tokens above, never raw numbers.
- Move search, category and filter controls that sit above the card into the toolbar. Keep the
  instances; do not detach.
- Move result-count text that sits above the card into the toolbar summary line.

## Validation (per candidate)

1. Card padding 0 and the table's left/right edges equal the card's edges?
2. Search / category / filters inside the card toolbar, in the order above?
3. Toolbar 16/20, footer 16/20, both bound to tokens; borders `colorBorderSecondary`?
4. Result count inside the card?
5. All yes → **Already correct**; otherwise list each mismatch. Unsure whether it is a data table → **Needs review**.
