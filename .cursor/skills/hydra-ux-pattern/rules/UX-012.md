# UX-012: Back Button on Sub-Pages

- **Category:** Navigation / Page header
- **Status:** Approved (2026-11-12, Milos)
- **Standard:** A page that is opened from another page in the same module shows a back button
  as the first item in `Content`, above the page title. It is a DS `Button`, type default, size
  medium, with the `LeftOutlined` icon on the left, labelled "Back to" plus the name of the page it
  returns to. The gap to the title is the page rhythm, 24px (`paddingLG`).
- **Reference:** BOM - RSFC, Parsing review "2.5 Parsing review, Full list" button `5913:13871`, and
  the Part Cross-Reference section `7560:210686` (screens 1.2 to 3.3).

## Spec

| Part | Rule |
|---|---|
| Component | DS `Button`, `type=default`, `size=medium`, `show icon left` on, icon `LeftOutlined`, no right icon |
| Label | "Back to" and the parent page name as the user sees it in the sidebar or breadcrumb, for example "Back to BOM" |
| Position | First child of `Content`, before the page header. Width hugs the label |
| Gap | `Content` item spacing `paddingLG` (24px), the same gap as between other page sections |
| Destination | Always the parent page in the module, not the browser history |
| Every state | The button stays on every state of the page: start, loading, results, empty, no results, error, and behind open modals |

## Applies when

- Sub-pages that the user opens from a module hub or list, for example Part Cross-Reference from
  the BOM hub, a detail page from a list, or a wizard step that starts from a hub.
- Every module file and the prototype code.

## Does not apply

- The module's entry page or hub, for example "1.1 BOM entry point".
- Pages opened straight from the sidebar.
- Modals, drawers and popovers. They close, they do not go back.
- Spec or documentation frames that are not real screens.
- Wizard steps that already have a Back action in their footer, unless the header back button is
  also in the design. Mark these as Needs review.

## Implementation

- Copy the reference instance or create it from the DS `Button` and set its properties. Do not
  detach it.
- Insert it at index 0 of `Content`. Do not add spacer frames; the `Content` gap gives the 24px.
- After adding it, check that absolutely placed layers that follow a control (open dropdowns,
  modal overlays) still line up, and that screens with a filling state card keep their height
  (UX-006, UX-009).

## Validation (per candidate)

1. Is the page opened from another page in the same module? If not, skip.
2. Is there a back button as the first item in `Content`?
3. Is it `Button` default, medium, left arrow icon, labelled "Back to" and the parent page name?
4. Is the gap to the title 24px from the `Content` item spacing?
5. All yes means **Already correct**. Otherwise list each mismatch. If it is unclear which page is
   the parent, mark it **Needs review**.

## Fix (only when explicitly requested)

Add or correct the button as in Implementation, keep everything else unchanged, then re-check
dropdown and overlay positions and take a screenshot before and after.
